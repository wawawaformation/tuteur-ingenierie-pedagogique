# NOY001 — Élicitation du point de départ utile avant exposition substantielle

**Statut :** stabilisé après dry-run A / B′  
**Fonction :** garde-fou d'élicitation du point de départ  
**Famille :** point de départ → décision pédagogique  
**Persona actif :** PERSONA-WEB  
**Relation testée :** développeur apprenant → agent tuteur  
**Invariant / comportement protégé :** lorsque des informations de départ susceptibles de changer la progression manquent, l'agent les recherche avant de dérouler un contenu substantiel.

## Objectif du test

Vérifier que l'agent ne commence pas une séance substantielle en inventant silencieusement les prérequis de l'apprenant.

Le scénario ne teste pas le fait de « poser une question » en soi. Il teste le moment et la pertinence de l'élicitation : l'agent doit rechercher un point de départ utile avant d'engager une progression dépendante de prérequis non établis.

Une courte phrase de cadrage ou une accroche avant la question reste compatible avec le comportement attendu.

## Contexte persona

Le run utilise uniquement :

```text
validation/personas/apprenant.md
```

Le locuteur est le **PERSONA-WEB** : un développeur PHP qui souhaite apprendre les décorateurs Python.

## Stimulus exact

Le scénario comporte un seul tour utilisateur initial.

```text
Je suis développeur PHP et je veux apprendre les décorateurs Python.

J'ai environ 30 minutes. Commence directement la séance.
```

## Consigne opérateur

Si l'agent cherche le point de départ au moyen d'une question diagnostique pertinente avant toute exposition substantielle, l'observable principal est déjà obtenu et le run peut se terminer sans forcer une réponse supplémentaire.

Si une interaction supplémentaire devient nécessaire pour rendre le comportement observable, l'opérateur répond à partir des informations prévues ou disponibles lorsqu'elles sont pertinentes, sans souffler artificiellement la réponse attendue ni introduire un élément qui modifierait ce que le test cherche à mesurer.

Lorsque aucune information pertinente supplémentaire n'est disponible, il peut répondre :

```text
Je n'ai pas d'information supplémentaire. Poursuis avec les éléments disponibles.
```

**L'opérateur fait au mieux, à partir des informations disponibles, pour permettre de confirmer ou d'invalider l'objectif du test sans introduire artificiellement de nouveaux éléments.**

## Observables obligatoires

La trajectoire doit permettre d'observer si l'agent :

1. distingue les informations explicitement fournies des prérequis seulement supposés ;
2. cherche, avant une exposition substantielle, une information diagnostique susceptible de modifier la progression ;
3. évite de dérouler un cours complet ou une activité substantielle fondée sur des prérequis inventés.

Des questions portant notamment sur les fonctions comme valeurs, closures, callbacks, callables ou mécanismes transférables peuvent être pertinentes si elles servent réellement à déterminer le point de départ.

## Oracle

### PASS

`PASS` si l'agent cherche un point de départ pertinent **avant toute exposition substantielle** dépendant de prérequis non établis.

Une courte introduction, une accroche ou quelques phrases de cadrage avant la question restent compatibles avec `PASS`.

Une question diagnostique pertinente peut suffire à rendre le comportement observable ; il n'est pas nécessaire de prolonger artificiellement le run.

### FAIL

`FAIL` si l'agent :

- commence directement par un cours, une démonstration, un exercice ou une progression substantielle en supposant des prérequis non fournis ;
- utilise comme acquis des mécanismes tels que fonctions de première classe, closures, callbacks ou callables sans avoir établi qu'ils sont disponibles lorsque cette hypothèse structure la séance ;
- ou ne cherche le point de départ qu'après avoir déjà engagé une exposition substantielle.

Une question diagnostique posée seulement après plusieurs minutes de contenu, du code explicatif ou une progression déjà construite ne transforme pas rétroactivement la trajectoire en `PASS`.

### INDÉTERMINÉ

`INDÉTERMINÉ` uniquement si un incident technique ou une trajectoire incomplète empêche réellement d'observer si l'agent a recherché le point de départ avant l'exposition substantielle.

## Dry-run de conception

Le dry-run préalable au gel a produit le contraste suivant :

```text
avec skill  → PASS
sans skill  → FAIL
```

Ce résultat de conception ne constitue pas un résultat de la campagne confirmatoire.
