# NOY004 — Alignement objectif / critère

**Statut :** stabilisé après dry-run A / B′  
**Test historique d’origine :** T12  
**Famille :** alignement pédagogique  
**Invariant protégé :** le critère de réussite doit permettre d’évaluer la performance réellement annoncée par l’objectif.

## Objectif du test

Vérifier que l’agent détecte un désalignement simple entre :

- un objectif demandant d’**expliquer avec ses propres mots** ;
- un critère demandant d’**écrire seul une fonction fonctionnelle avec trois tests**.

Le test reste volontairement court. Il ne cherche pas à couvrir toute la chaîne d’ingénierie pédagogique dans un même scénario.

## Prompt exact

```text
Crée une activité dont l'objectif est :
« Expliquer avec ses propres mots ce qu'est une fonction PHP. »

Le critère de réussite sera :
« L'apprenant écrit seul une fonction PHP fonctionnelle avec trois tests. »
```

## Observables obligatoires

La réponse doit permettre d’observer si l’agent :

1. détecte que l’objectif vise une performance d’**explication / compréhension** ;
2. détecte que le critère vise une performance de **mise en œuvre / application** ;
3. signale explicitement le désalignement ;
4. propose une correction cohérente au lieu d’accepter silencieusement l’ensemble tel quel.

## Oracle

### PASS

`PASS` si la réponse :

- identifie explicitement le désalignement entre l’objectif et le critère ;
- et propose au moins une correction cohérente, par exemple :
  - conserver l’objectif et adopter un critère portant réellement sur l’explication ;
  - conserver le critère et reformuler l’objectif vers la mise en œuvre ;
  - séparer les deux performances en activités ou évaluations distinctes.

Il n’est pas nécessaire d’utiliser les termes « taxonomie », « Comprendre », « Appliquer » ou « alignement constructif » si le problème est correctement identifié et traité.

### FAIL

`FAIL` si la réponse :

- accepte l’objectif et le critère tels quels sans signaler leur désalignement ;
- ou ajoute une activité d’explication mais conserve malgré tout comme seul critère de réussite l’écriture d’une fonction fonctionnelle avec trois tests ;
- ou mentionne une différence entre les deux sans la traiter réellement.

L’ajout d’une explication dans le déroulé ou dans une grille secondaire ne suffit pas si le critère de réussite annoncé reste uniquement technique et que la réponse ne signale pas le problème.

### INDÉTERMINÉ

`INDÉTERMINÉ` uniquement si la réponse est trop incomplète ou ambiguë pour déterminer si le désalignement a été détecté et traité.

Une interruption technique relève de la validité technique du run, pas d’`INDÉTERMINÉ`.

## Consigne opérateur

Envoyer le prompt exact en un seul tour.

Ne pas signaler à l’agent qu’il existe un problème d’alignement et ne pas suggérer de correction.

Si l’agent pose une question après avoir déjà produit suffisamment d’éléments pour appliquer l’oracle, le run peut s’arrêter sans réponse supplémentaire.

Conserver le verbatim intégral.

**L’opérateur fait au mieux, à partir des informations disponibles, pour permettre de confirmer ou d’invalider l’objectif du test sans introduire artificiellement de nouveaux éléments.**

## Validité technique

Le run est techniquement valide si :

- le prompt exact est envoyé sans ajout pédagogique ;
- aucun persona n’est injecté ;
- les conditions A et B′ reçoivent le même stimulus ;
- le verbatim intégral est disponible ;
- aucune intervention opérateur ne révèle le désalignement ou la correction attendue.

## Contre-garde-fou

NOY004 ne demande pas que l’objectif et le critère utilisent exactement le même verbe.

Le comportement protégé est simplement :

```text
la preuve exigée pour réussir
doit permettre de conclure sur
la performance annoncée par l’objectif
```

Une tâche plus riche ou plus exigeante peut être légitime, à condition que la conclusion d’évaluation reste correctement alignée.

## Dry-run de stabilisation

Résultat observé avec le prompt PHP ci-dessus :

```text
A  avec skill : PASS
B′ sans skill : FAIL
```

Le contraste est obtenu sans deuxième tour, sans persona et sans enrichissement du scénario.
