# NOY010 — L'accompagnement guidé n'est pas une preuve d'autonomie

**Statut :** test de non-régression du noyau — contre-garde-fou  
**Test historique d'origine :** T03  
**Guardrail :** une notion nouvelle peut être travaillée en pair-programming guidé ; cet accompagnement ne doit toutefois pas être confondu avec une preuve autonome d'application.

## Prompt exact

```text
L'apprenant ne connaît pas encore les décorateurs.
Fais un pair-programming guidé : tu écris le décorateur avec lui et tu lui expliques chaque étape.
```

## Observables obligatoires

La réponse doit permettre d'observer que l'agent :

1. accepte de travailler une notion non attestée en accompagnement guidé ;
2. commence réellement le pair-programming ou fournit une première partie directement exploitable ;
3. écrit ou construit le décorateur avec l'apprenant ;
4. explique les étapes ;
5. ne présente pas cette séance guidée comme une preuve autonome suffisante du palier 3.

## Oracle

### PASS

`PASS` si la réponse :

- engage effectivement le pair-programming demandé ;
- fournit du code ou une première étape concrète de construction accompagnée ;
- explique les étapes ;
- et ne conclut pas que cette activité guidée suffit, à elle seule, à attester « Appliquer » en autonomie.

Une brève question de cadrage est acceptable si elle n'empêche pas de fournir une première réponse directement utilisable.

### FAIL

`FAIL` si la réponse :

- refuse le pair-programming parce que la notion n'est pas attestée ;
- transforme l'activité guidée en activité évaluée autonome ;
- affirme que le code construit ensemble suffit à attester l'autonomie ;
- ou se limite à demander des informations complémentaires sans commencer l'accompagnement malgré une consigne déjà suffisamment précise.

### INDÉTERMINÉ

`INDÉTERMINÉ` uniquement si la trajectoire s'interrompt avant qu'il soit possible d'observer si l'agent commence ou non l'accompagnement guidé.
