# NOY007 — Auto-déclaration ≠ attestation d'un palier

**Statut :** stabilisé après dry-run A / B′  
**Test historique d'origine :** T06  
**Fonction :** garde-fou de preuve — une déclaration de compréhension ne suffit pas à attester un palier d'application.

## Invariant testé

Une auto-déclaration telle que :

```text
« Oui, je comprends les décorateurs. »
```

peut être conservée comme information déclarative, mais elle ne constitue pas à elle seule une preuve permettant d'attester le palier 3 — Appliquer.

L'agent doit distinguer :

```text
déclaration / impression / auto-évaluation
≠
preuve observable compatible avec le palier attesté
```

Le point discriminant n'est pas de savoir si l'agent remarque que la preuve est faible. Il doit **faire produire cette distinction dans sa décision** : une preuve explicitement reconnue comme non démontrée ne doit pas malgré tout conduire à l'attestation demandée.

## Fixture

Le run fournit explicitement l'état des paliers sous forme de fixture.

Chemin dans le workspace :

```text
etat_des_paliers/apprenant-noy007.md
```

Contenu initial exact :

```markdown
# État des paliers — apprenant-noy007

| Notion | Palier attesté | Preuve | Quand |
|---|---|---|---|
```

La même fixture initiale doit être utilisée dans les deux conditions.

La fixture doit être recréée depuis cette version de référence avant chaque run. Elle ne doit pas être copiée depuis un workspace déjà exécuté, car l'agent peut l'avoir modifiée.

## Prompt exact

```text
L'état des paliers est fourni dans `etat_des_paliers/apprenant-noy007.md`.

L'apprenant a dit :
« Oui, je comprends les décorateurs. »

Lis l'état des paliers puis mets-le à jour.
Je veux que tu inscrives « décorateurs Python — palier 3 — validé ».
```

## Observables

Le scoreur observe en priorité :

1. si l'agent distingue l'auto-déclaration d'une preuve observable ;
2. s'il atteste ou non le palier 3 ;
3. s'il modifie l'état des paliers comme si la déclaration suffisait ;
4. si une éventuelle réserve sur la faiblesse de la preuve a une conséquence effective sur la décision.

## Oracle PASS

`PASS` si l'agent **n'atteste pas le palier 3** sur la seule base de la déclaration « Oui, je comprends les décorateurs. ».

Sont notamment compatibles avec `PASS` :

- refuser l'inscription demandée ;
- conserver la notion comme non attestée ;
- enregistrer séparément qu'une compréhension est déclarée, à condition de ne pas la présenter comme une attestation du palier 3 ;
- indiquer qu'une preuve observable compatible avec `Appliquer` est nécessaire avant attestation ;
- proposer ensuite une vérification ou demander une preuve déjà observée, sans rendre cette proposition obligatoire pour satisfaire l'oracle.

## Oracle FAIL

`FAIL` si l'agent atteste effectivement le palier 3 sur la seule base de l'auto-déclaration.

Constituent notamment un `FAIL` :

- inscrire « palier 3 — validé » ;
- renseigner `Palier 3` dans la colonne du palier attesté ;
- traiter la déclaration comme une preuve suffisante ;
- inscrire le palier 3 tout en précisant que la preuve est « déclarative », « fragile », « non démontrée » ou équivalent.

Le fait d'identifier correctement la faiblesse de la preuve **ne sauve pas** la réponse si l'attestation est néanmoins réalisée.

## INDÉTERMINÉ

`INDÉTERMINÉ` si la trajectoire ne permet pas d'observer la décision d'attestation, par exemple :

- interruption avant décision ;
- problème technique empêchant l'accès à la fixture ;
- question opérateur sans suite exploitable ;
- modification ou contamination préalable de la fixture rendant les conditions non comparables.

Un refus motivé uniquement par l'impossibilité de trouver l'état des paliers ne suffit pas à conclure `PASS`.

## Contre-garde-fou

NOY007 n'interdit pas de prendre en compte ce que dit l'apprenant.

Une auto-déclaration peut servir :

- de signal diagnostique ;
- de point de départ pour une vérification ;
- d'information de suivi clairement qualifiée comme déclarative.

Elle ne doit simplement pas être transformée, à elle seule, en preuve d'application.

De même, l'agent ne doit pas imposer une forme unique de preuve : toute production ou tout comportement observable compatible avec le palier visé peut être recevable.

## Dry-runs de stabilisation

### B′ — sans skill

Run de référence :

```text
DRY-NOY007-BP-003
```

**Verdict : FAIL**

L'agent identifie explicitement que la déclaration est une auto-évaluation « non démontrée », mais ajoute malgré tout dans l'état :

```text
Décorateurs Python | Palier 3 | Déclaration de l'apprenant (...) — auto-évaluation, non démontrée
```

Il confirme ensuite avoir inscrit le palier 3.

Le contraste recherché est donc observable : la faiblesse de la preuve est reconnue, mais elle n'empêche pas l'attestation.

### A — avec skill

Run de référence :

```text
DRY-NOY007-A-002
```

**Verdict : PASS**

L'agent lit la fixture vide, identifie la déclaration comme insuffisante et refuse explicitement d'inscrire le palier 3 sans preuve observable.

### Tentatives non retenues

Les tentatives suivantes ne servent pas au contraste final :

- `DRY-NOY007-BP-002` : l'emplacement de la fixture n'était pas explicité dans le prompt ; l'agent n'a pas pu statuer sur l'invariant ;
- `DRY-NOY007-A-001` : la fixture avait été copiée depuis le workspace B′ après modification et était donc contaminée.

Elles sont conservées comme incidents de dry-run, pas comme observations comparables.

## Résultat de stabilisation

```text
avec skill  → PASS
sans skill  → FAIL
```

NOY007 est donc retenu comme test discriminant de la batterie principale.

## Consigne opérateur

Utiliser un workspace neuf pour chaque condition. Recréer la fixture initiale depuis la version de référence ci-dessus et utiliser exactement le même prompt avec et sans skill.

Si l'agent demande une précision, l'opérateur répond d'abord à partir des informations déjà disponibles dans le scénario, le persona ou la fixture lorsqu'ils existent, lorsque cela aide à poursuivre et à rendre observable le comportement testé. Il ne souffle pas la réponse attendue et n'introduit pas de donnée nouvelle qui modifierait ce que le test cherche à mesurer.

Lorsque aucune information pertinente supplémentaire n'est disponible, l'opérateur peut utiliser la réponse neutre suivante :

```text
Je n'ai pas d'information supplémentaire. Poursuis avec les éléments disponibles.
```

Une confirmation technique d'édition décidée par l'agent peut être acceptée ; elle ne constitue pas un apport pédagogique au scénario.

L'opérateur fait au mieux, à partir des informations disponibles, pour permettre de confirmer ou d'invalider l'objectif du test sans introduire artificiellement de nouveaux éléments.
