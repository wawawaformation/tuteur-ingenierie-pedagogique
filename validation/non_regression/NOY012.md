# NOY012 — Découverte du catalogue de gabarits et représentation correcte de l’architecture

**Statut :** stabilisé — baseline A observée en FAIL avant modification du skill  
**Fonction :** test de découvrabilité et de représentation du catalogue de gabarits  
**Famille :** gabarits → catalogue → architecture → contextes d’usage  
**Persona actif :** PERSONA-FORMATEUR-FPA  
**Relation testée :** formateur → agent assistant pédagogique  
**Condition :** A uniquement — avec skill  
**Invariant / comportement protégé :** l’agent doit connaître et présenter correctement les gabarits d’Activité qu’il a à disposition, sans les confondre avec les niveaux de découpage pédagogique et sans enfermer leurs usages dans des modalités rigides.

## Objectif du test

Vérifier que l’agent possède une représentation correcte et exploitable de sa propre bibliothèque de gabarits d’Activité.

La réponse doit permettre à un formateur de comprendre :

```text
quels gabarits d’Activité existent
→ à quoi chacun sert
→ dans quels contextes il peut être pertinent
```

sans transformer les exemples d’usage en contraintes exclusives.

Le test observe trois dimensions liées mais distinctes :

```text
catalogue
→ identifier les vrais gabarits d’Activité

architecture
→ distinguer Module / Séquence / Séance / Activité

héritage
→ comprendre que les gabarits spécialisés
  sont des formes d’Activité
```

## Invariant testé

Le découpage pédagogique de référence est :

```text
Module
└── Séquence
    └── Séance
        └── Activité
```

`Activité` est le niveau de granularité le plus fin.

Les gabarits spécialisés sont des formes d’Activité, par exemple :

```text
Activité
├── Brique
├── Atelier
├── Quiz
├── Recul
└── autres gabarits futurs
```

Ils ne doivent pas être présentés comme des niveaux concurrents de `Activité`.

Les contextes d’usage servent à orienter le choix :

```text
finalité
+ besoin pédagogique
+ contexte
+ modalité
→ pertinence possible d’un gabarit
```

Ils ne constituent pas une table rigide du type :

```text
Atelier = asynchrone uniquement
Quiz = asynchrone uniquement
Recul = après Atelier uniquement
```

sauf contrainte intrinsèque réellement documentée.

## Contexte / Fixture

Aucune fixture technique ni état préalable n’est nécessaire.

Le run utilise uniquement :

```text
validation/personas/formateur.md
```

Le locuteur est un formateur qui demande à l’agent de lui présenter les gabarits d’activité disponibles et leurs contextes possibles d’utilisation.

## Trajectoire opérateur

### Tour 1 — Prompt exact

```text
Je suis formateur et j'aimerais connaître les gabarits d'activité que tu as à ta disposition.

Pour chacun, indique-moi brièvement à quoi il sert et dans quels contextes je pourrais l'utiliser.
```

### Si l’agent demande des informations supplémentaires

L’opérateur répond à partir des informations déjà disponibles dans le scénario, le persona ou la fixture lorsqu’elles permettent de poursuivre sans modifier l’objet du test.

Il ne complète pas artificiellement le scénario pour provoquer le comportement attendu.

Si aucune information pertinente supplémentaire n’est disponible, il peut utiliser :

```text
Je n'ai pas d'information supplémentaire. Poursuis avec les éléments disponibles.
```

Puis laisser l’agent poursuivre sa réponse.

## Consigne opérateur

Utiliser un workspace neuf avec skill et injecter uniquement `validation/personas/formateur.md`.

Envoyer le stimulus exactement tel qu’il est défini ci-dessus.

Ne pas fournir la liste attendue des gabarits.

Ne pas expliquer la hiérarchie `Module → Séquence → Séance → Activité`.

Ne pas indiquer que Brique, Atelier, Quiz ou Recul sont des spécialisations d’Activité.

Ne pas corriger l’agent s’il associe un gabarit à une modalité de manière rigide : cette affirmation fait partie des observables du test.

Si l'agent demande une précision, l'opérateur répond d'abord à partir des informations déjà disponibles dans le scénario, le persona ou la fixture lorsqu'ils existent, lorsque cela aide à poursuivre et à rendre observable le comportement testé. Il ne souffle pas la réponse attendue et n'introduit pas de donnée nouvelle qui modifierait ce que le test cherche à mesurer.

Lorsque aucune information pertinente supplémentaire n'est disponible, l'opérateur peut utiliser la réponse neutre suivante :

```text
Je n'ai pas d'information supplémentaire. Poursuis avec les éléments disponibles.
```

L’opérateur fait au mieux, à partir des informations disponibles, pour permettre de confirmer ou d’invalider l’objectif du test sans introduire artificiellement de nouveaux éléments.

## Périmètre de notation

Le verdict porte sur la représentation du catalogue et de l’architecture observable dans la réponse finale.

Le test ne demande pas à l’agent de produire une activité.

### Hors périmètre

Ne pas scorer dans NOY012 :

- la conformité détaillée du contenu de chaque gabarit ;
- la présence de toutes les rubriques internes ;
- la qualité exhaustive des exemples pédagogiques ;
- la séparation apprenant / formateur ;
- le choix d’un gabarit pour une situation précise ;
- la qualité stylistique générale de la réponse.

Ces dimensions relèvent d’autres NOY.

## Observables

Le scoreur observe notamment :

1. quels éléments l’agent présente comme « gabarits d’activité » ;
2. s’il mélange dans ce catalogue des niveaux de découpage tels que Syllabus, Module, Séquence ou Séance ;
3. s’il présente `Activité` comme le niveau de granularité commun ;
4. s’il comprend que Brique, Atelier, Quiz, Recul et autres formats spécialisés sont des formes d’Activité ;
5. s’il présente Activité et Atelier comme deux catégories concurrentes ;
6. s’il décrit correctement la finalité générale de chaque gabarit ;
7. s’il formule les contextes d’usage comme des possibilités ou comme des exclusivités ;
8. s’il enferme un gabarit dans une modalité synchrone/asynchrone ou présentiel/distanciel ;
9. s’il invente des gabarits qui ne sont pas réellement disponibles.

## Oracle

Appliquer l’oracle dans l’ordre suivant.

### Étape 1 — FAIL

Le run est `FAIL` si au moins une des situations suivantes est observable :

1. l’agent présente comme gabarits d’Activité des niveaux de découpage tels que `Séquence` ou `Séance` sans les distinguer clairement de la bibliothèque de gabarits ;
2. l’agent présente `Activité` et `Atelier` comme deux formats concurrents alors qu’Atelier est une spécialisation d’Activité ;
3. l’agent nie ou ne reconnaît pas l’existence d’un socle `Activité` commun aux gabarits spécialisés ;
4. l’agent affirme qu’un gabarit est réservé par définition à une modalité sans contrainte intrinsèque justifiant cette exclusivité ;
5. l’agent présente les contextes d’usage comme une table rigide `contexte/modalité → gabarit` ;
6. l’agent invente un ou plusieurs gabarits inexistants de manière substantielle ;
7. la réponse globale donne au formateur une représentation structurellement fausse de la bibliothèque disponible.

Une seule erreur structurelle majeure suffit à établir le `FAIL`.

### Étape 2 — PASS

Si aucune condition de `FAIL` n’est remplie, le run est `PASS` si l’agent :

- distingue correctement les niveaux de découpage pédagogique des gabarits d’Activité ;
- présente `Activité` comme la brique de granularité la plus fine ;
- présente les gabarits spécialisés comme des formes d’Activité ;
- liste les gabarits réellement disponibles sans invention substantielle ;
- explique brièvement leur finalité ;
- donne des contextes possibles d’utilisation sans les transformer en exclusivités artificielles ;
- permet au formateur de comprendre la « boîte à outils » disponible et de s’orienter vers un gabarit pertinent.

L’ordre de présentation, les intitulés exacts et le niveau de détail ne sont pas imposés.

### Étape 3 — INDÉTERMINÉ

Le run est `INDÉTERMINÉ` si la trajectoire est techniquement valide mais que la réponse reste trop vague pour déterminer si l’agent distingue réellement les niveaux de découpage des gabarits d’Activité.

Un problème de workspace, de persona, de chargement du skill, de session ou de collecte relève d’une **invalidité technique**, pas d’`INDÉTERMINÉ`.

## Contre-garde-fous

NOY012 ne signifie pas :

```text
tous les gabarits doivent convenir à tous les contextes
```

Un gabarit peut avoir des usages plus fréquents ou des contraintes particulières.

Le test protège seulement l’absence d’associations artificiellement exclusives et la représentation correcte de l’architecture.

Il ne signifie pas non plus que `Séance`, `Séquence` ou `Syllabus` sont inutiles.

Ces éléments peuvent être mentionnés pour expliquer le découpage global, à condition qu’ils ne soient pas présentés comme faisant partie du catalogue des gabarits d’Activité.

## Validité technique

Le run est techniquement valide si :

- le workspace est neuf ;
- le candidat V2 courant est bien utilisé ;
- le skill est présent et chargé dans la condition A ;
- `validation/personas/formateur.md` est le seul persona injecté ;
- le prompt exact est envoyé sans ajout préalable ;
- l’opérateur ne fournit aucune taxonomie attendue ;
- les autorisations techniques nécessaires à la lecture du skill n’ajoutent aucune information pédagogique au stimulus ;
- le verbatim complet de la trajectoire est disponible.

Une erreur technique, une mauvaise condition ou une contamination du stimulus impose un rerun ou une exclusion avant scoring.

## Contrôle des interventions opérateur

Toute intervention hors prompt exact doit être conservée dans le verbatim.

Les confirmations techniques de lecture de fichiers ou d’exécution de commandes nécessaires à Claude Code ne contaminent pas le test.

Le run devient techniquement invalide si l’opérateur souffle par exemple :

```text
Atelier est un type d’Activité.
Séance n’est pas un gabarit d’Activité.
Un Quiz peut être synchrone.
Présente Module → Séquence → Séance → Activité.
```

## Limites reconnues

NOY012 teste la **découvrabilité et la représentation du catalogue**, pas la qualité détaillée des gabarits eux-mêmes.

Un PASS ne garantit pas que l’agent choisira toujours correctement un gabarit en situation réelle : ce point est protégé par NOY010.

Un PASS ne garantit pas non plus que le gabarit choisi héritera correctement du socle Activité : ce point est protégé par NOY009.

## Baseline V2 observée avant modification

La première exécution A sur le candidat courant a produit une représentation structurellement incorrecte.

L’agent a notamment présenté dans une même liste de « gabarits » :

```text
Syllabus Augmenté
Séquence
Séance
Atelier
Activité
Quiz
Recul
```

Il a ensuite décrit :

```text
Séance → synchrone
Atelier → asynchrone
```

et a présenté `Activité` et `Atelier` comme deux formats distincts et concurrents :

> « Différence clé avec l'Atelier : si ça nécessite une section “Méthode proposée”, ce n'est plus une Activité. »

Cette réponse montre que le candidat actuel :

```text
connaît les fichiers
mais
ne représente pas correctement leur architecture
```

La baseline est donc :

```text
NOY012 — A = FAIL
```

Le défaut observé correspond directement à l’objectif de la V2 :

```text
avant
→ catalogue dispersé
→ niveaux et gabarits mélangés
→ usages enfermés par modalité

objectif V2
→ Activité comme socle commun
→ gabarits spécialisés correctement identifiés
→ métadonnées orientant le routage
→ contextes possibles, non exclusifs
```
