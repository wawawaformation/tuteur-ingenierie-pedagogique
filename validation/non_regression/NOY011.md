# NOY011 — Maîtrise de l’exposition dans une activité évaluée

**Statut :** révisé — le caractère évalué est désormais explicite dans le stimulus  
**Fonction :** test de protection de la valeur de preuve par maîtrise de l’exposition  
**Famille :** gabarits → évaluation → exposition → séparation apprenant / formateur  
**Persona actif :** PERSONA-FORMATEUR-FPA  
**Relation testée :** formateur → agent assistant pédagogique  
**Condition :** A uniquement — avec skill  
**Invariant / comportement protégé :** lorsqu’une activité est explicitement évaluée et que sa production doit servir de preuve, les critères utiles restent accessibles à l’apprenant mais la solution, la correction et les indices décisifs ne doivent pas lui être fournis avant sa production au point d’annuler ce que l’on prétend observer.

## Objectif du test

Vérifier que l’agent sait distinguer deux situations pédagogiques qui ne doivent pas être confondues :

```text
faire apprendre
→ guidage, démonstration, indice ou échafaudage possibles

évaluer pour produire une preuve
→ préserver ce que l’apprenant doit réellement produire ou décider
```

NOY011 ne cherche donc pas à interdire l’aide pédagogique.

Il vérifie que, lorsque le stimulus établit **noir sur blanc** que l’activité est évaluée et que la production finale doit servir de preuve, l’agent maîtrise l’exposition des informations :

```text
côté apprenant
→ objectif / tâche / données / contraintes
→ critères de réussite ou de performance
→ sans solution ni correction décisive avant la production évaluée

côté formateur
→ attendus détaillés
→ éléments d’observation
→ correction / solution
→ éléments de débrief
```

Le test ne demande pas obligatoirement deux documents séparés.

La séparation peut être documentaire, visuelle, temporelle ou fonctionnelle, à condition qu’elle soit directement exploitable.

## Invariant testé

Pour une activité explicitement évaluée :

```text
critères visibles
≠ solution révélée

aide avant ou pendant l’apprentissage
≠ preuve autonome

réussite après indice décisif
≠ attestation automatique d’une réalisation autonome
```

Un indice ou une démonstration n’est pas mauvais en soi.

Si l’agent choisit de guider fortement l’apprenant, il peut le faire comme acte de formation ; il doit alors préserver la distinction entre cette réussite accompagnée et la preuve autonome recherchée.

Le défaut testé est donc :

```text
révéler ce qui fait précisément l’objet de l’évaluation
puis
traiter la production obtenue comme si cette information n’avait pas été donnée
```

## Contexte / Fixture

Aucune fixture technique ni état préalable n’est nécessaire.

Le run utilise uniquement :

```text
validation/personas/formateur.md
```

Le locuteur est un formateur qui prépare une activité SQL évaluée et demande l’ensemble des éléments nécessaires pour la lancer, observer les productions et faire le retour final.

Le stimulus établit certains prérequis afin que NOY011 n’ait pas pour objet de tester A3 ou le diagnostic initial.

## Trajectoire opérateur

### Tour 1 — Prompt exact

```text
Je prépare un atelier de 30 minutes sur SQL.

Les apprenants disposent de deux tables :

clients(id, nom, ville)
commandes(id, client_id, total)

Ils ont déjà pratiqué et réussi seuls des requêtes avec une jointure simple, `GROUP BY` + `SUM`, ainsi que le remplacement d'une valeur `NULL` par une valeur par défaut.

Ils doivent maintenant produire une requête qui donne, pour chaque client, le montant total de ses commandes, en conservant aussi les clients qui n'ont encore passé aucune commande.

Cet atelier est évalué : la requête finale doit me servir de preuve de leur capacité à résoudre ce cas.

Prépare-moi l'atelier complet pour demain, avec ce qu'il me faut pour le lancer, observer les productions et faire le retour à la fin.
```

### Si l’agent demande des informations supplémentaires

L’opérateur répond à partir des informations déjà disponibles dans le scénario et le persona lorsque cela permet de poursuivre sans modifier l’objet du test.

Il ne précise pas spontanément la solution SQL, le type de jointure attendu, ni la manière de séparer les contenus.

Si aucune information pertinente supplémentaire n’est disponible, il peut utiliser :

```text
Je n'ai pas d'information supplémentaire. Poursuis avec les éléments disponibles.
```

Puis laisser l’agent poursuivre sa réponse.

## Consigne opérateur

Utiliser un workspace neuf avec skill et injecter uniquement `validation/personas/formateur.md`.

Envoyer le stimulus exactement tel qu’il est défini ci-dessus.

Ne pas demander explicitement :

- de séparer les contenus apprenant et formateur ;
- de masquer la solution ;
- d’ajouter une correction ;
- d’ajouter une grille formateur ;
- d’indiquer ce qui peut être distribué aux apprenants ;
- de protéger la valeur de preuve.

Si l’agent demande une précision, l’opérateur répond d’abord à partir des informations déjà disponibles dans le scénario, le persona ou la fixture lorsqu’ils existent, lorsque cela aide à poursuivre et à rendre observable le comportement testé. Il ne souffle pas la réponse attendue et n’introduit pas de donnée nouvelle qui modifierait ce que le test cherche à mesurer.

Lorsque aucune information pertinente supplémentaire n’est disponible, l’opérateur peut utiliser la réponse neutre suivante :

```text
Je n'ai pas d'information supplémentaire. Poursuis avec les éléments disponibles.
```

Toute intervention supplémentaire doit être conservée dans le verbatim.

L’opérateur fait au mieux, à partir des informations disponibles, pour permettre de confirmer ou d’invalider l’objectif du test sans introduire artificiellement de nouveaux éléments.

## Périmètre de notation

Le verdict porte sur la **maîtrise de l’exposition dans la production finale complète**, dans le contexte explicitement évalué du stimulus.

Le fait que la réponse globale adressée au formateur contienne une solution SQL n’est pas un défaut.

Le scoreur vérifie surtout :

- ce qui est prévu pour l’apprenant **avant sa production évaluée** ;
- ce qui est réservé au formateur ou à un temps postérieur à cette production ;
- si un éventuel guidage modifie correctement la nature de la preuve que l’agent prétend pouvoir tirer de la réussite.

### Hors périmètre

Ne pas scorer dans NOY011 :

- le choix du mot `Atelier` ou `Séance` ;
- l’association éventuelle d’un gabarit à une modalité ;
- le nombre exact de rubriques du gabarit ;
- la qualité exhaustive du SQL proposé ;
- la doctrine de nouveauté, les prérequis utiles étant fournis dans le stimulus ;
- la qualité détaillée de la progression ;
- l’usage d’un outil particulier.

Ces dimensions relèvent d’autres invariants, notamment NOY010 pour le routage/modalité.

## Observables

Le scoreur observe notamment :

1. si une partie directement utilisable avec les apprenants avant la production évaluée est identifiable ;
2. si cette partie contient les informations nécessaires pour réaliser l’activité ;
3. si les critères de réussite ou de performance utiles à l’apprenant sont explicites ;
4. si la solution SQL ou les éléments de correction sont protégés jusqu’à la production évaluée ;
5. si des indices présents avant cette production donnent pratiquement la décision technique que l’activité doit précisément permettre d’observer ;
6. si les éléments d’observation sont disponibles au formateur ;
7. si la correction ou solution attendue est disponible au formateur ;
8. si la frontière entre apprentissage accompagné, production évaluée et correction est suffisamment claire ;
9. si une réussite obtenue après un guidage décisif est encore présentée à tort comme preuve d’une réalisation autonome.

## Oracle

Appliquer l’oracle dans l’ordre suivant.

### Étape 1 — FAIL

Le run est `FAIL` si au moins une des situations suivantes est observable :

1. la solution ou correction attendue apparaît dans ce qui doit être remis aux apprenants **avant leur production évaluée**, au point de leur fournir directement la réponse à produire ;
2. un indice décisif fourni avant la production évaluée révèle pratiquement la décision technique qui constitue l’objet de la preuve, **sans que l’agent réduise en conséquence la portée de cette preuve** ;
3. les contenus apprenant et formateur sont mélangés de telle manière qu’une distribution directe du support apprenant révélerait des éléments réservés à la correction avant la production évaluée ;
4. aucun élément de correction, solution ou attendu détaillé n’est fourni au formateur alors que la demande porte explicitement sur l’observation des productions et le retour final ;
5. la réponse ne permet pas d’identifier ce qui doit être exposé avant l’évaluation et ce qui doit rester réservé au formateur ou à l’après-production ;
6. l’agent organise un fort échafaudage donnant la solution puis présente malgré tout la réussite ainsi obtenue comme une preuve équivalente d’autonomie.

Une aide pédagogique n’est donc pas un `FAIL` par elle-même : le `FAIL` apparaît lorsque l’exposition annule ce que l’activité prétend encore évaluer ou attester.

### Étape 2 — PASS

Si aucune condition de `FAIL` n’est remplie, le run est `PASS` si la production :

- fournit une partie exploitable par les apprenants ;
- rend les critères utiles explicites ;
- protège la solution et les éléments décisifs de correction jusqu’à la production évaluée ;
- fournit au formateur les attendus nécessaires pour observer et corriger ;
- rend disponible une solution ou correction exploitable côté formateur ou après production ;
- distingue suffisamment les destinataires ou les moments d’exposition ;
- permet au formateur de guider ou remédier lorsque nécessaire **sans confondre ensuite réussite accompagnée et preuve autonome**.

Les intitulés exacts `Volet apprenant` et `Volet formateur` ne sont pas imposés.

Une séparation fonctionnellement ou temporellement équivalente est recevable.

### Étape 3 — INDÉTERMINÉ

Le run est `INDÉTERMINÉ` si la trajectoire est techniquement valide mais que la production ne permet pas de déterminer avec suffisamment de certitude quelles informations sont exposées avant la production évaluée et quelles informations sont réservées à la correction ou à l’après-production.

Un problème de workspace, de persona, de chargement du skill, de session ou de collecte relève d’une **invalidité technique**, pas d’`INDÉTERMINÉ`.

## Contre-garde-fous

NOY011 ne signifie pas :

```text
en formation, il ne faut jamais aider
```

Une activité formative, une démonstration, une pratique accompagnée ou une remédiation peuvent légitimement :

- fournir des indices ;
- guider étape par étape ;
- montrer une partie de la méthode ;
- aller jusqu’à expliciter une solution lorsque l’objectif est de faire apprendre.

Le test ne transforme donc pas toute divulgation en faute.

Il protège uniquement la cohérence entre :

```text
ce qui a été donné
→ ce que l’apprenant a réellement dû produire ou décider
→ ce que l’on prétend ensuite avoir prouvé
```

Dans une activité évaluée, un formateur peut aussi intervenir après une première production ou donner un indice pour permettre de poursuivre. La réussite obtenue après cette aide reste utile pédagogiquement, mais sa portée de preuve doit être ajustée.

NOY011 ne signifie pas non plus que la réponse adressée au formateur ne doit jamais contenir la solution.

Au contraire, un formateur a besoin des réponses ou attendus pour préparer, observer, corriger et conduire le débrief.

Enfin, le test n’impose pas deux documents séparés : une réponse unique est acceptable si la frontière entre les destinataires ou les moments d’exposition est suffisamment nette.

## Validité technique

Le run est techniquement valide si :

- le workspace est neuf ;
- le candidat V2 courant est bien utilisé ;
- le skill est présent et chargé dans la condition A ;
- `validation/personas/formateur.md` est le seul persona injecté ;
- le prompt exact est envoyé sans ajout préalable ;
- l’opérateur ne souffle ni la séparation attendue ni la solution technique ;
- le verbatim complet de la trajectoire est disponible.

Une erreur technique, une mauvaise condition ou une contamination du stimulus impose un rerun ou une exclusion avant scoring.

## Contrôle des interventions opérateur

Toute intervention hors prompt exact doit être conservée dans le verbatim.

Une réponse opérateur fondée sur les informations déjà disponibles ne contamine pas le test tant qu’elle ne souffle ni la solution technique ni le comportement d’exposition attendu.

La réponse neutre peut être utilisée lorsqu’aucune information pertinente supplémentaire n’est disponible.

Le run devient techniquement invalide si l’opérateur souffle par exemple :

```text
Fais une partie apprenant sans correction.
Ajoute ensuite une partie formateur avec la solution.
Ne montre pas le type de jointure aux apprenants.
Sépare les deux volets.
```

## Limites reconnues

NOY011 protège la maîtrise de l’exposition **dans une activité explicitement évaluée**.

Un PASS ne démontre pas que tous les gabarits et toutes les activités gèrent correctement cette séparation.

Le test ne dit pas jusqu’où un formateur doit guider dans toutes les situations de formation.

Il ne doit surtout pas être utilisé pour conclure qu’un fort échafaudage est mauvais en soi.

Il vérifie seulement que le niveau d’aide réellement fourni reste cohérent avec la portée de preuve que l’activité prétend produire.

## Baseline historique avant révision du stimulus

Une exécution antérieure sur le candidat avait produit une séparation explicite entre :

```text
Énoncé remis aux apprenants
```

et :

```text
Volet formateur — à ne pas remettre aux apprenants
```

avec solution SQL, grille de correction et éléments de débrief côté formateur.

Cette exécution était `PASS` sur l’ancien stimulus, qui ne disait pas explicitement que l’activité était évaluée.

Elle est conservée comme **repère historique de non-régression de la séparation des destinataires**, mais elle ne constitue plus une baseline strictement comparable au scénario révisé.

Le scénario actuel doit donc être rejoué sur le candidat V2 avant d’être considéré comme stabilisé.
