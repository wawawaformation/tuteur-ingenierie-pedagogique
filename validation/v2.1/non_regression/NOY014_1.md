# NOY014_1 — Référence spécialisée contradictoire sans dérogation explicite : le noyau prévaut

**Statut :** candidat V2.1 — instrument corrigé après audit méthodologique  
**Famille :** NOY — architecture / préséance documentaire / dérogation locale  
**Condition officielle :** A uniquement — avec skill  
**Nature :** non-régression architecturale  
**Prérequis de gel :** contrôle C0 documenté dans `CONTROLE_STABILISATION_NOY014.md`

---

## 1. Objectif

Vérifier la branche négative de la règle de préséance :

```text
référence spécialisée contradictoire
sans dérogation explicitement signalée
→
le noyau prévaut
```

Le mécanisme testé est une règle de résolution de priorité documentaire.

Il ne constitue pas :

- un gate supplémentaire ;
- une obligation de rechercher systématiquement des dérogations ;
- une préférence générale pour les références spécialisées ;
- une autorisation de remplacer implicitement le noyau.

---

## 2. Règle générale utilisée comme contraste

Le scénario s'appuie sur la règle générale du noyau :

```text
Activité = granularité la plus fine
```

Avant gel de l'instrument, vérifier dans le noyau runtime courant que cette règle existe bien avec cette portée.

La référence spécialisée artificielle contient une règle locale contradictoire :

```text
Activité
└── Micro-activité
```

mais **ne la signale pas comme une dérogation explicite au noyau**.

---

## 3. Fixture

Dans une copie temporaire et neuve du skill candidat, installer :

```text
references/mock.md
```

avec le contenu exact de :

```text
mock_sans_derogation.md
```

Le fichier `mock.md` est une fixture de test.

Il ne fait pas partie du candidat publié.

Aucun autre fichier du skill ne doit être modifié spécifiquement pour ce run.

---

## 4. Stimulus exact

```text
Le travail suivant relève du périmètre `MOCK-GRANULARITE`.

La référence `references/mock.md` fait partie du skill chargé et concerne ce périmètre.

Structure une Activité composée de deux étapes successives :
1. lire une consigne ;
2. produire une réponse.

Donne uniquement la structure hiérarchique.
```

Le stimulus :

- désigne la référence pertinente afin de ne pas tester sa découverte ;
- ne dit pas quelle règle doit prévaloir ;
- ne qualifie pas `mock.md` de dérogation ;
- ne fournit pas la structure attendue.

---

## 5. Consigne opérateur

Utiliser :

- une session neuve ;
- une copie neuve du candidat ;
- la condition A ;
- aucun persona injecté ;
- mémoire automatique désactivée selon les conventions de la campagne.

Envoyer le stimulus exactement tel qu'il est défini.

Si l'agent demande quelle règle doit prévaloir ou s'il doit appliquer `mock.md`, répondre une seule fois :

```text
Applique les règles du skill pertinentes pour ce périmètre à partir des éléments disponibles.
```

Une demande de clarification suivie d'une décision propre de l'agent n'est pas en soi un `FAIL`.

Ne fournir aucune autre indication sur :

- le noyau ;
- le conflit ;
- la règle de préséance ;
- la présence ou l'absence d'une dérogation.

L'opérateur fait au mieux, à partir des informations disponibles, pour permettre de confirmer ou d'invalider l'objectif du test sans introduire artificiellement de nouveaux éléments.

Toute intervention supplémentaire est conservée dans le verbatim.

---

## 6. Observable de lecture — obligatoire

Le PASS de cette branche n'est interprétable que si la trajectoire montre que :

```text
references/mock.md
```

a effectivement été **lu ou chargé avant la production finale**.

La trace d'outil ou le verbatim doit permettre de l'établir.

Si `mock.md` n'a pas été lu ou si sa consultation n'est pas observable, la sortie conforme au noyau pourrait résulter d'une simple non-consultation de la référence.

Dans ce cas :

```text
verdict = INDÉTERMINÉ
```

et non `PASS`.

---

## 7. Comportement attendu

La règle locale de `mock.md` contredit le noyau mais n'est pas explicitement signalée comme une dérogation.

Le noyau doit donc prévaloir.

La production peut organiser les deux éléments comme :

- étapes ;
- items ;
- sous-parties descriptives ;

mais ne doit pas introduire `Micro-activité` comme nouvelle granularité formelle sous `Activité`.

Exemple compatible :

```text
Activité
├── Étape 1 : lire une consigne
└── Étape 2 : produire une réponse
```

---

## 8. Oracle

Appliquer l'oracle dans l'ordre suivant.

### Étape 1 — INDÉTERMINÉ pour absence de lecture observable

Le verdict est `INDÉTERMINÉ` si la trajectoire ne permet pas d'établir que `references/mock.md` a été lu ou chargé avant la production finale.

Cette règle prime sur un éventuel résultat textuel conforme au noyau.

### Étape 2 — FAIL

Si la lecture de `mock.md` est établie, le verdict est `FAIL` si l'agent :

- utilise `Micro-activité` comme niveau structurel sous `Activité` sur le fondement de la règle locale ;
- affirme qu'une règle spécialisée prévaut sur le noyau alors qu'aucune dérogation n'est explicitement signalée ;
- traite implicitement toute règle spécialisée comme prioritaire ;
- renvoie durablement la décision de préséance à l'utilisateur et ne tranche pas lui-même, y compris après la relance neutre prévue ;
- signale le conflit mais décide néanmoins d'appliquer la règle locale comme si elle constituait une dérogation valide.

Un FAIL établit que le comportement attendu n'est pas obtenu.

Le diagnostic ultérieur pourra distinguer notamment :

```text
préférence générale pour la règle locale
```

de :

```text
contradiction détectée mais règle de préséance mal appliquée
```

Cette distinction diagnostique ne modifie pas le verdict.

### Étape 3 — PASS

Si `mock.md` a été lu et qu'aucune condition de `FAIL` n'est remplie, le verdict est `PASS` si l'agent :

- conserve `Activité` comme granularité la plus fine ;
- n'utilise pas `Micro-activité` comme niveau structurel formel.

Le modèle n'est pas obligé d'expliquer la préséance.

Des libellés comme :

```text
Étape 1
Étape 2
```

restent compatibles avec `PASS` : ils décrivent l'organisation interne de l'activité sans créer une nouvelle granularité formelle.

### Autres cas INDÉTERMINÉ

Utiliser également `INDÉTERMINÉ` si, malgré une lecture observable de `mock.md`, la sortie ne permet réellement pas de déterminer si `Micro-activité` est utilisé comme niveau structurel ou seulement comme terme descriptif sans statut hiérarchique.

---

## 9. Validité technique

Le run est techniquement exploitable si :

- la condition est A ;
- le skill candidat prévu est chargé ;
- le noyau runtime courant contient bien la règle générale utilisée comme contraste ;
- la session est neuve ;
- la copie du skill est neuve ;
- `references/mock.md` contient exactement `mock_sans_derogation.md` ;
- aucun autre fichier du skill n'est modifié spécifiquement pour le run ;
- le stimulus exact est joué ;
- le verbatim complet est conservé ;
- aucune explication de la préséance attendue n'est fournie par l'opérateur.

La non-consultation de `mock.md` ne rend pas le run techniquement invalide : elle conduit à `INDÉTERMINÉ` selon le §8.

Le run est techniquement invalide si :

- la mauvaise fixture est injectée ;
- une règle concurrente artificielle est ajoutée ;
- l'opérateur explique quelle règle doit gagner ;
- le candidat est modifié spécialement pour produire l'issue attendue.

---

## 10. Limites

NOY014_1 ne teste pas :

- la découverte spontanée d'une référence spécialisée ;
- plusieurs références spécialisées concurrentes ;
- la sortie du périmètre après application d'une règle locale ;
- une dérogation métier réelle ;
- la hiérarchie entre deux dérogations explicites.

Il teste uniquement :

```text
contradiction locale
+
absence de dérogation explicite
→
noyau
```

Une règle locale bornée à un périmètre peut être interprétée par certains modèles comme une dérogation implicite. Si cela survient, le verdict reste déterminé par l'oracle ; cette interprétation doit être conservée pour le diagnostic et ne transforme pas rétroactivement la règle en dérogation explicite.

---

## 11. Règle de répétition

Après gel :

```text
premier A FAIL
→ deux reruns
→ seulement ensuite diagnostic
```

Les reruns servent à mesurer la reproductibilité et ne constituent pas un vote majoritaire.

Ne jamais modifier simultanément l'oracle et le skill pour faire disparaître un FAIL.
