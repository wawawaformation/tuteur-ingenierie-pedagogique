# NOY014_2 — Dérogation locale explicite : la règle spécialisée prévaut

**Statut :** candidat V2.1 — instrument corrigé après audit méthodologique  
**Famille :** NOY — architecture / préséance documentaire / dérogation locale  
**Condition officielle :** A uniquement — avec skill  
**Nature :** non-régression architecturale  
**Prérequis de gel :** contrôle C0 documenté dans `CONTROLE_STABILISATION_NOY014.md`

---

## 1. Objectif

Vérifier la branche positive de la règle de préséance :

```text
référence spécialisée contradictoire
avec dérogation explicitement signalée
→
la règle spécialisée prévaut
→
uniquement dans son périmètre
```

Le mécanisme testé est une règle de résolution de priorité documentaire.

Il ne constitue pas :

- un gate supplémentaire ;
- une obligation de rechercher systématiquement des dérogations ;
- une préférence générale pour les références spécialisées ;
- une autorisation de modifier implicitement le noyau hors du périmètre déclaré.

---

## 2. Règle générale utilisée comme contraste

Le scénario s'appuie sur la règle générale du noyau :

```text
Activité = granularité la plus fine
```

Avant gel de l'instrument, vérifier dans le noyau runtime courant que cette règle existe bien avec cette portée.

La référence spécialisée artificielle introduit dans le périmètre `MOCK-GRANULARITE` :

```text
Activité
└── Micro-activité
```

et signale explicitement que cette règle constitue une dérogation locale à la règle générale du noyau.

---

## 3. Fixture

Dans une copie temporaire et neuve du skill candidat, installer :

```text
references/mock.md
```

avec le contenu exact de :

```text
mock_avec_derogation.md
```

Le fichier `mock.md` est une fixture de test.

Il ne fait pas partie du candidat publié.

Aucun autre fichier du skill ne doit être modifié spécifiquement pour ce run.

---

## 4. Stimulus exact

```text
Le travail suivant relève du périmètre `MOCK-GRANULARITE`.

La référence `references/mock.md` fait partie du skill chargé et concerne ce périmètre.

Structure une Activité composée de deux étapes successives :
1. lire une consigne ;
2. produire une réponse.

Donne uniquement la structure hiérarchique.
```

Le stimulus est volontairement identique à celui de NOY014_1.

Il ne dit pas quelle règle doit prévaloir.

---

## 5. Consigne opérateur

Utiliser :

- une session neuve ;
- une copie neuve du candidat ;
- la condition A ;
- aucun persona injecté ;
- mémoire automatique désactivée selon les conventions de la campagne.

Ne pas réutiliser la session ou la copie de skill de NOY014_1.

Envoyer le stimulus exactement tel qu'il est défini.

Si l'agent demande quelle règle doit prévaloir ou s'il doit appliquer `mock.md`, répondre une seule fois :

```text
Applique les règles du skill pertinentes pour ce périmètre à partir des éléments disponibles.
```

Une demande de clarification suivie d'une décision propre de l'agent n'est pas en soi un `FAIL`.

Ne fournir aucune autre indication sur la règle de préséance.

L'opérateur fait au mieux, à partir des informations disponibles, pour permettre de confirmer ou d'invalider l'objectif du test sans introduire artificiellement de nouveaux éléments.

Toute intervention supplémentaire est conservée dans le verbatim.

---

## 6. Observable principal

Lorsque la dérogation explicite prévaut, l'agent doit réellement appliquer la granularité spécialisée :

```text
Activité
├── Micro-activité : lire une consigne
└── Micro-activité : produire une réponse
```

Ici, `Micro-activité` est le nom du niveau structurel défini par la référence spécialisée.

Son emploi est donc un observable direct de l'application de cette règle.

---

## 7. Oracle

Appliquer l'oracle dans l'ordre suivant.

### Étape 1 — FAIL

Le verdict est `FAIL` si l'agent :

- refuse d'utiliser `Micro-activité` au motif que le noyau fait d'`Activité` la granularité la plus fine ;
- applique le noyau à la place de la règle spécialisée malgré la dérogation explicitement signalée ;
- signale une contradiction comme non résolue alors que la référence contient une dérogation explicite et bornée ;
- ignore la règle spécialisée applicable ;
- renvoie durablement la décision de préséance à l'utilisateur et ne tranche pas lui-même, y compris après la relance neutre prévue.

### Étape 2 — PASS

Si aucune condition de `FAIL` n'est remplie, le verdict est `PASS` si l'agent représente les deux étapes comme deux `Micro-activités` sous l'`Activité`.

Exemple :

```text
Activité
├── Micro-activité : lire une consigne
└── Micro-activité : produire une réponse
```

Le libellé `Micro-activité` est attendu : il ne s'agit pas ici d'une chaîne arbitraire à recopier mais du nom du niveau structurel défini par la règle locale.

Une explication de la dérogation est autorisée mais non requise.

### Étape 3 — INDÉTERMINÉ

Utiliser `INDÉTERMINÉ` si la sortie est techniquement exploitable mais ne permet réellement pas de déterminer si la granularité locale a été appliquée.

## 8. Validité technique

Le run est techniquement exploitable si :

- la condition est A ;
- le skill candidat prévu est chargé ;
- le noyau runtime courant contient bien la règle générale utilisée comme contraste ;
- la session est neuve ;
- la copie du skill est neuve ;
- `references/mock.md` contient exactement `mock_avec_derogation.md` ;
- aucun autre fichier du skill n'est modifié spécifiquement pour le run ;
- le stimulus exact est joué ;
- le verbatim complet est conservé ;
- aucune explication de la préséance attendue n'est fournie par l'opérateur.

Le run est techniquement invalide si :

- la mauvaise fixture est injectée ;
- NOY014_1 et NOY014_2 sont joués dans la même conversation ;
- une règle concurrente artificielle est ajoutée ;
- l'opérateur explique quelle règle doit gagner ;
- le candidat est modifié spécialement pour produire l'issue attendue.

## 9. Lecture conjointe avec NOY014_1

La lecture attendue des deux runs officiels est :

```text
NOY014_1
sans dérogation explicite
→ noyau

NOY014_2
avec dérogation explicite
→ spécialisée
```

Un résultat :

```text
spécialisée dans les deux cas
```

suggère une préférence générale pour la référence locale.

Un résultat :

```text
noyau dans les deux cas
```

suggère que la dérogation explicite n'est pas opérationnelle.

Les verdicts restent attribués séparément ; cette lecture conjointe sert au diagnostic architectural.

---

## 10. Limites

NOY014_2 ne teste pas :

- la découverte spontanée des références spécialisées ;
- plusieurs références spécialisées concurrentes ;
- la sortie du périmètre après application de la dérogation ;
- une dérogation réelle métier ;
- une dérogation partielle à une règle complexe.

Il teste uniquement :

```text
dérogation locale explicite
+
périmètre applicable
→
règle spécialisée
```

---

## 11. Règle de répétition

Après gel :

```text
premier A FAIL
→ deux reruns
→ seulement ensuite diagnostic
```

Les reruns servent à mesurer la reproductibilité et ne constituent pas un vote majoritaire.

Ne jamais modifier simultanément l'oracle et le skill pour faire disparaître un FAIL.
