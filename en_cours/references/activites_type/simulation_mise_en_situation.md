# GABARIT : Simulation / mise en situation

Faire agir l'apprenant dans une situation proche d'un contexte de référence et observer comment il mobilise ses acquis dans l'action.

La Simulation / mise en situation est une **Activité d'action contextualisée**.

Elle place l'apprenant dans une situation construite pour reproduire, de manière suffisamment fidèle, certaines caractéristiques d'une situation réelle ou professionnelle.

L'apprenant ne se contente pas d'analyser ce qu'il faudrait faire : il doit **agir, décider, produire ou interagir dans la situation**.

## Pourquoi choisir une Simulation / mise en situation ?

Choisir une Simulation lorsque l'objectif consiste à observer si l'apprenant sait **mobiliser ses acquis dans l'action**.

Elle permet notamment de travailler :

- l'application d'une procédure ;
- la prise de décision ;
- l'adaptation à une situation ;
- l'utilisation d'un outil ;
- la gestion d'une interaction ;
- la mobilisation simultanée de plusieurs acquis ;
- la prise en compte de contraintes ;
- la réaction à un événement ou une difficulté ;
- l'autonomie dans une situation proche du contexte de référence.

Elle est particulièrement pertinente lorsqu'il existe un écart entre :

> savoir expliquer ce qu'il faudrait faire

et :

> être capable de le faire effectivement en situation.

## Niveaux taxonomiques

La Simulation se prête naturellement aux niveaux :

- **Appliquer** : exécuter une procédure, utiliser une méthode ou mobiliser des acquis ;
- **Analyser** : identifier les caractéristiques de la situation et adapter son action ;
- **Évaluer** : comparer plusieurs possibilités et choisir une réponse à partir de critères.

Elle peut également mobiliser **Créer** lorsque l'apprenant doit élaborer une réponse ou une stratégie nouvelle.

> Le niveau réellement travaillé dépend de l'action demandée et des décisions à prendre.

## Quand la choisir ?

Elle est adaptée pour :

- préparer une situation professionnelle ;
- entraîner une procédure ;
- exercer une interaction ;
- vérifier la capacité à agir sous contraintes ;
- observer une prise de décision ;
- entraîner l'adaptation face à un imprévu ;
- vérifier qu'une connaissance peut être mobilisée hors du contexte exact où elle a été apprise.

Elle n'est pas nécessaire lorsque l'objectif consiste principalement à examiner une situation et argumenter une réponse sans agir : une Étude de cas peut alors être plus adaptée.

## Situation de référence

Identifier :

- ce que l'apprenant devra savoir faire ;
- les caractéristiques pertinentes de la situation ;
- les contraintes à prendre en compte ;
- les décisions ou comportements à observer.

La simulation n'a pas besoin de reproduire toute la réalité.

> Le réalisme est au service de l'apprentissage ; il n'est pas un objectif en soi.

## Rôle de l'apprenant

Définir clairement ce que l'apprenant doit accomplir.

Il peut devoir :

- réaliser une opération ;
- utiliser un outil ;
- répondre à une demande ;
- conduire un entretien ;
- résoudre un incident ;
- prendre une décision ;
- coordonner plusieurs actions ;
- interagir avec une ou plusieurs personnes ;
- produire un résultat dans un contexte donné.

## Contexte et contraintes

Fournir seulement les informations nécessaires à l'action :

- situation initiale ;
- objectif ;
- ressources ;
- acteurs ;
- règles ;
- données ;
- outils ;
- contraintes de temps ;
- événements ;
- limites ou restrictions.

Une difficulté périphérique ne doit pas masquer la compétence réellement travaillée.

## Consigne / tâche à réaliser

La consigne précise :

- la situation ;
- le rôle ;
- le résultat attendu ;
- les contraintes ;
- les ressources disponibles.

Elle ne doit pas détailler à l'avance toutes les décisions lorsque celles-ci font précisément partie de la performance à observer.

## Déroulement

Une Simulation peut comprendre :

1. présentation du contexte ;
2. attribution éventuelle des rôles ;
3. mise à disposition des ressources ;
4. action de l'apprenant ;
5. événement ou contrainte éventuelle ;
6. fin de la situation ;
7. débriefing.

Toutes les étapes ne sont pas obligatoires.

## Événements et imprévus

Lorsque l'objectif le justifie, la situation peut évoluer.

Un événement peut :

- modifier une contrainte ;
- apporter une information nouvelle ;
- invalider une hypothèse ;
- créer un incident ;
- obliger à reconsidérer une décision.

Les imprévus doivent servir une performance identifiable.

## Observation

Déterminer à l'avance ce qui doit être observable :

- actions ;
- ordre des opérations ;
- décisions ;
- informations recherchées ;
- utilisation des ressources ;
- respect des contraintes ;
- argumentation ;
- adaptation ;
- interactions ;
- résultat produit.

## Débriefing

Revenir sur :

- les décisions prises ;
- les informations utilisées ;
- les difficultés rencontrées ;
- les stratégies mobilisées ;
- les écarts entre intention et action ;
- les conséquences des choix ;
- les alternatives possibles ;
- ce qui pourrait être modifié lors d'une nouvelle tentative.

Lorsque cela est pertinent, demander d'abord à l'apprenant d'analyser sa propre action.

## Nouvelle tentative

Une nouvelle tentative peut permettre d'observer si l'apprenant sait :

- modifier sa stratégie ;
- intégrer le feedback ;
- corriger une procédure ;
- agir avec moins d'aide ;
- répondre à une variation.

Une première simulation guidée ne constitue pas à elle seule une preuve d'autonomie.

## Critères de réussite / performance

Ils peuvent notamment concerner :

- la pertinence des décisions ;
- le respect d'une procédure ;
- la prise en compte des contraintes ;
- l'utilisation appropriée des ressources ;
- la qualité d'une interaction ;
- la capacité d'adaptation ;
- la cohérence entre analyse et action ;
- le résultat obtenu ;
- le degré d'autonomie.

## Contrôles avant de livrer la Simulation

1. **Finalité** : l'apprenant doit réellement agir.
2. **Situation de référence** : les éléments reproduits sont pertinents.
3. **Action observable** : il ne se contente pas d'expliquer ce qu'il ferait.
4. **Réalisme utile** : aucune complexité gratuite.
5. **Cohérence avec l'objectif** : les actions permettent d'observer la performance visée.
6. **Niveau taxonomique** : il correspond à l'action effectivement demandée.
7. **Guidage** : la consigne ne fournit pas les décisions à mobiliser.
8. **Débriefing** : un retour sur l'action est prévu lorsque pertinent.
9. **Preuve** : réussite avec aide et réussite autonome sont distinguées.
10. **Budget de nouveauté** : appliquer `../activite_evaluee.md` lorsque nécessaire.
